## 2. Secrets Management & AI Studio Integration

### 2.1 The AI Studio Secrets Panel & `.env` Pattern
In compliance with cloud development container guidelines, sensitive credentials (e.g., `GEMINI_API_KEY`) are managed exclusively via the **AI Studio Secrets Panel** and injected into the build system via `.env` files.

> [!CAUTION]
> **Zero Hardcoded Secrets Policy**: Hardcoding API keys or secrets in source code, Kotlin files, or Git-tracked XML files is strictly prohibited. `local.properties` is never used or created, as containerized developer environments rely on pre-configured environment variables.

### 2.2 Template Configuration (`.env.example`)
```bash
# Similimum AI Environment Configuration Template
# Place the active file at project root as '.env'

# Google Gemini API Key (Obtained from Google AI Studio)
GEMINI_API_KEY=AIzaSyD-EXAMPLE-PRODUCTION-KEY-DO-NOT-COMMIT

# Model Deployment Identifier
GEMINI_MODEL=gemini-2.5-flash

# Inference Network Timeouts (milliseconds)
GEMINI_CONNECT_TIMEOUT_MS=5000
GEMINI_READ_TIMEOUT_MS=10000

# Emergency Red-Flag Strict Mode (true = instant banner on regex hit)
CLINICAL_RED_FLAG_STRICT_MODE=true

# Database Encryption Key Alias in AndroidKeyStore
DB_KEYSTORE_ALIAS=SimilimumMasterKeyAlias
```

## 3. BuildConfig Injection via Gradle Kotlin DSL

The Gradle build configuration reads environment variables safely and injects strongly typed constants into the generated `BuildConfig` class:

```kotlin
// In app/build.gradle.kts
import java.io.FileInputStream
import java.util.Properties

val envFile = rootProject.file(".env")
val envProperties = Properties()
if (envFile.exists()) {
    envProperties.load(FileInputStream(envFile))
}

android {
    defaultConfig {
        // Safe injection with fallback to environment variables
        val apiKey: String = envProperties.getProperty("GEMINI_API_KEY")
            ?: System.getenv("GEMINI_API_KEY")
            ?: ""

        buildConfigField("String", "GEMINI_API_KEY", "\"$apiKey\"")
        buildConfigField("String", "GEMINI_MODEL", "\"gemini-2.5-flash\"")
        buildConfigField("long", "GEMINI_CONNECT_TIMEOUT_MS", "5000L")
        buildConfigField("long", "GEMINI_READ_TIMEOUT_MS", "10000L")
        buildConfigField("boolean", "CLINICAL_RED_FLAG_STRICT_MODE", "true")
    }

    buildTypes {
        release {
            isMinifyEnabled = true
            isShrinkResources = true
            proguardFiles(
                getDefaultProguardFile("proguard-android-optimize.txt"),
                "proguard-rules.pro"
            )
            buildConfigField("boolean", "ENABLE_DEBUG_LOGGING", "false")
        }
        debug {
            isMinifyEnabled = false
            buildConfigField("boolean", "ENABLE_DEBUG_LOGGING", "true")
        }
    }
}
```

## 4. Keystore Hygiene & Key Rotation

1. **Debug Keystore**:
   - `debug.keystore` is auto-generated by the container environment and never modified or committed to public version control.
2. **Production Release Keystore**:
   - Stored as a GitHub Actions encrypted repository secret (`ANDROID_RELEASE_KEYSTORE_BASE64`).
   - Injected into runner memory only during tag-triggered release builds and immediately purged.
   - Dual-algorithm signing: RSA 4096-bit with SHA-256 digest, adhering to APK Signature Scheme v2, v3, and v4.
3. **Android Keystore Provider for SQLCipher**:
   - Generates an AES-256 GCM master key stored inside the device's hardware Secure Element / StrongBox (`AndroidKeyStore`).
   - If the device lacks a hardware StrongBox, the key is stored in the Trusted Execution Environment (TEE).

`[ASSUMPTION-OPS-02]` API keys are injected at build time via BuildConfig sourced from environment variables; the app functions 100% offline with zero degradation if no key is present.
